# 高配当株スクリーナー（自動収集版）

東証プライム・スタンダードの全銘柄から、リベ大式の条件に合う高配当株を自動で抽出し、
予算に合わせたポートフォリオを組むアプリです。データ収集は GitHub Actions が自動で行います。

- データ源：Yahoo Finance（yfinance）＋ JPX上場銘柄一覧
- 更新：毎週土曜の朝に自動。Actions の「Run workflow」で手動実行も可能
- 公開：GitHub Pages（docs フォルダ）

## セットアップ（約15分）

1. GitHub にログインし、右上「＋」→「New repository」。名前は `kabu-screener` など。Public のまま「Create repository」
2. 「uploading an existing file」をクリックし、この ZIP を解凍した中身（`.github` `docs` `screen.py` `requirements.txt` `README.md` `.gitignore`）を**フォルダごと**ドラッグ＆ドロップ → 「Commit changes」
   - `.github` フォルダが見えない場合は、Mac は Cmd+Shift+. / Windows はエクスプローラーの「隠しファイルを表示」を有効にしてください
3. リポジトリの **Settings → Actions → General → Workflow permissions** で「Read and write permissions」を選んで Save
4. **Settings → Pages** で Source を「Deploy from a branch」、Branch を `main` / `/docs` にして Save
5. **Actions タブ → 「高配当株データ更新」→ Run workflow**。初回は全銘柄を取得するため 1〜3 時間かかります（2回目以降はキャッシュで短縮）
6. 完了後、`https://ユーザー名.github.io/リポジトリ名/` を開くと最新データが読み込まれます

## テスト実行したいとき

Actions の実行前に、`screen.py` の動作だけ確かめたい場合は、ワークフロー画面で環境変数を変えずに
リポジトリ設定 → Secrets and variables → Actions → Variables に `UNIVERSE_LIMIT = 50` を追加すると 50 銘柄だけで数分で終わります（確認後に削除）。

## v7.1：実ブラウザでの点検とスマホ対応

- スマホで「4. 将来」「5. 買付」のタブが画面外に隠れていた → タブ名を短くして5つとも表示
- 買付タブはリストを先頭に表示し、設定は折りたたみに。表は「銘柄・買う数・金額・口座」の順
- 長いETF名で表が押し広げられ「買う数」が見えなかった → 銘柄名を折り返し
- 横に続きがある表は右端に影を表示（ダークモード対応）
- ETFの割合を「組んだ中での比率」で守るよう修正（日本株を組みきれない時にETF比率が膨らんでいた）
- 買付リストの端数処理を改善（1口が高いETFの分だけ余る月があった → 毎月ほぼ全額を使う）

## v7：段階型（リベ大優先＋A補完）

- 新しい戦略「段階型」を追加し、初期値に設定
- リベ大式の基準に合格した銘柄を最優先で選び、2倍の比率で配分（1銘柄5%の上限まで）。足りない分をパターンAの基準の銘柄で埋める
- リベ大式の合格が増えるほど、新しいお金がそちらに優先して回り、保有のリベ大基準の比率が自然に上がる
- 買い増しの対象から外れたA基準の保有は売らずに保有継続（「買い増しを止めている保有」として案内）
- ポートフォリオと買付タブに「リベ大基準の比率」を表示
- 補足：S株の場合、リベ大式が全額を投資できるかは保有額ではなく「合格銘柄の数」で決まる（1銘柄5%上限のため20銘柄以上が必要）

## v6：毎月の買付リスト

### 毎月の使い方（5分）
1. アプリを開く（保有が登録済みなら「5. 今月の買付」が自動で開く）
2. 今月の投資額を確認（初期値は月20万円）
3. リストどおりにSBI証券で注文（S株・預り区分はNISA）。「メモをコピー」で注文内容をメモに貼れる
4. 「注文した分を保有に反映」を押す → 翌月はその続きから計算
5. 「確認が必要な保有」が出たら、その銘柄のIRを確認（減配・条件外れ）

### 仕組み
- 選んだ戦略の理想の配分を「今の保有額＋今月の投資額」で計算し、不足が大きい銘柄から買う
- 注文数の上限（初期値10件/月）、1件の最低購入額（初期値3,000円）で注文の手間を抑える
- すでに持っている銘柄を優先して残すので、毎月の入れ替えが起きにくい
- NISA成長枠は年240万円・生涯残りを自動で差し引き。非課税の効果が大きい日本株から先にNISAに入れる
- 保有とNISA使用額はこの端末のブラウザに保存。機種変更やスマホ・PC併用時は「バックアップを書き出す」→もう一方で「貼り付けた内容で置き換え」

## v5：S株（1株単位）を基本に

- 日本株の購入単位の初期値を「1株（S株）」に。毎月の積立の初期値はNISA成長枠に合わせて月20万円
- 「組み入れる銘柄数の上限」を追加（リベ大式40・パターンA30・パターンB25）。条件の達成数が多い順に選び、1業種に偏らないよう業種ごとの数も制限
- 大きな予算・1株単位で処理が終わらなくなる不具合を修正（配分計算を一括計算方式に変更）
- スクリーニング表は最初150行、「もっと見る」で追加表示（スマホでの表示を高速化）

## v4：NISA成長投資枠と米国高配当ETFに対応

- 口座を「NISA 成長投資枠」「特定口座（課税）」から選べます（初期値はNISA・年240万円）
- NISA分の配当は日本株100%・米国ETF90%（現地10%はNISAでは戻らない）、枠を超えた分は課税口座として手取りを計算
- 将来シミュレーションは、年240万円・生涯1,200万円の枠を年ごとに消化し、満杯後は課税口座に回す計算
- 米国部分は「高配当ETF（VYM・HDV・SPYD）」「個別株」「使わない」から選択。初期値はETF
- 米国の割合は戦略ごとではなく、自分で決める設定に変更（初期値30%）
- NISAの予算規模では日本株を自動でS株（1株単位）にして、1銘柄の上限を守りながら分散

## v3：米国株（S&P500）に対応

- 日本株に加えて、S&P500採用の米国株（SBI証券でほぼすべて取扱い）を自動収集します
- 判定の考え方は両学長の基準と同じ（高配当・減配しにくい・稼ぐ力・右肩上がり）。物差しだけ米国の実情に合わせています
  - 利回り：米国市場は全体の利回りが低いため、基準を日本より0.5〜0.75ポイント低めに設定
  - 財務の安全性：自社株買いで自己資本が小さい米国企業が多いため、自己資本比率の代わりに「返済年数（有利子負債−現金）÷営業CF」で判定
  - 現金の増加：米国企業は現金を自社株買いで還元するため、初期設定では判定に使いません
- ポートフォリオは米国株の上限（初期値40%）、1株単位、ドル円換算、米国配当の二重課税（手取り約72%）を反映
- 10年予測の不況シナリオでは、円高による米国株配当の目減り（15%）も織り込みます
- 米国株を収集しない場合は、ワークフローの `COUNTRIES` を `JP` にしてください

## v2 の主な変更（点検・最適化）

- 一次選別を導入：全銘柄の株価と直近1年配当を一括取得し、利回り2.5%未満は財務を取りに行かない（API呼び出しを大幅削減、初回の実行時間も短縮）
- レート制限対策：指数バックオフ付きリトライ、財務の30日キャッシュ
- 英字入りの新しい証券コード（130A など）に対応、ETF・外国株を除外
- 利回りは「直近1年の実績配当」で計算。記念配当・データ異常の疑いがある銘柄は ⚠ 表示し自動ポートフォリオから除外
- EPSの右肩上がり判定は株式分割の影響を受けにくい純利益で判定
- 景気シグナル（TOPIX連動ETFの200日平均・半年騰落、VIX、米10年金利、ドル円）を取得
- アプリ：3パターンの10年予測（好況・平常・不況）と推奨パターンの自動表示、将来試算の過大評価を修正

## 注意

- GitHub の仕様で、リポジトリに60日間動きがないと定期実行が止まることがあります。止まったら Actions 画面の案内に従って再開してください


- Yahoo Finance のデータは非公式で、欠損や誤りが混じることがあります。購入前は必ず IR や決算資料で確認してください
- このアプリは判断材料を整理する道具であり、投資助言ではありません
